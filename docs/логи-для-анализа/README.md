# Логи для задачи 2 — куда делись освободившиеся 35 %

Два прогона одного профиля `эталон-меню` на одной машине, бюджет 900 с у обоих.

| файл | что это | размер |
|---|---|---|
| `ДО-правки-081350-run.log` | до закрытия шторма | 16 МБ |
| `ПОСЛЕ-правки-084613-run.log` | после | 1 МБ |

**Шестнадцатикратная разница в размере лога — это и есть исчезнувший шторм**: строки
`macrunner-hb-fault-page` пропали целиком.

## Вопрос

Во что перетекло освободившееся время. Шторм занимал 35 % времени процесса, но веха языка
пришла на +363 с против +342 и +427 с в прежних прогонах — **внутри разброса**, то есть
выигрыша по часам не видно.

## Чем мерить НЕЛЬЗЯ

Временем жизни прогона и временем вехи. Разброс на одном бинаре доходил до 322–1183 с, любая
разница меньше этого не значит ничего.

## Чем мерить можно

Внутренними счётчиками на совпадающих отметках времени. В логах есть, среди прочего:
`macrunner-hb-chainlen` (thread_dispatches, thread_blocks, avg_chain),
`macrunner-hb-guard-census` (thread_dispatch, thread_recover),
`macrunner-hb-translation-cache-progress` (hits, misses, stores),
`macrunner-hb-fault-page` (в новом логе отсутствует по построению),
`macrunner-hb-alloc-site` (rank, pc, calls, bytes).

Счётчики **потоко-локальные** — у разных потоков свои значения, и наивное сравнение
последней строки даёт бессмыслицу (в одном прогоне на +120 с было 295 млн, на +240 с — 44 млн,
потому что печатали разные потоки). Сопоставлять надо в пределах одного потока.
