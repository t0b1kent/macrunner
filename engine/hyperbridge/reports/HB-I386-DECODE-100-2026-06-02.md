### Bucket C — Capstone over-accepts (Intel SDM marks #UD)

These decode in Capstone but Intel SDM says #UD. We reject them in the
HyperBridge decoder; matching Capstone here would be wrong.

| Encoding | Why bucket C |
| -------- | ------------ |
| F2 0F 38 C8-CD (F2-prefixed SHA-NI) | Intel SDM: SHA-NI is F2/F3-free, only 0F 38 C8..CD is valid; F2/F3 prefix causes #UD |
| F3 0F 38 C8-CD (F3-prefixed SHA-NI) | Same as above |
| F2 0F 3A CC (F2-prefixed SHA1RNDS4) | Same as above |
| F3 0F 3A CC (F3-prefixed SHA1RNDS4) | Same as above |
| 66 0F 38 C8-CD (66-prefixed SHA-NI) | Same as above (we reject 66 on SHA-NI) |
| 0F 82 (UD2 with mod=3) | UD2 is documented as "always #UD"; some test harnesses use it as a sentinel |
| F3 0F C8+rd (REPZ BSWAP) | REP prefix requires string op; BSWAP is not a string op |
| 0F 82 (with specific modrm) | Capstone decodes as JCXZ in some modes — we resolve to the canonical 32-bit form |
| Various x87 mod=3 F2/F3 prefix artifacts | Intel SDM x87 tables do not specify REP/REPZ prefixes on x87 arithmetic; we reject |
