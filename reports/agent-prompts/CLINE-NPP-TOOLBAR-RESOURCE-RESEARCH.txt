=== ЗАЧЕМ ===
Codex строит tiny probe, который должен воспроизвести ТОЧНО тот путь, которым Notepad++
загружает иконки тулбара. Сейчас есть догадка «RT_BITMAP resource 0x05ed», но она не
подтверждена. Если NPP грузит тулбар иначе (PNG/32bpp/свой декодер/CreateMappedBitmap),
probe по угаданному BITMAP-ID даст ложный результат. Нужно из исходника NPP узнать ТОЧНО:
каким API и из какого ресурса строится toolbar ImageList.

=== ЧТО НАЙТИ (Notepad++ open source, github.com/notepad-plus-plus/notepad-plus-plus) ===
1. Как создаётся toolbar ImageList: какой API — ImageList_Create + ImageList_AddMasked /
   LoadImage / LoadBitmap / CreateMappedBitmap / Gdiplus PNG-decode / своя функция?
   Искать: Toolbar, ToolBar.cpp/.h, reBarTop, _toolBarIcons, ImageList, TB_SETIMAGELIST,
   setToolBarIcons, IDR_*TOOLBAR*, LoadImage, AddBitmap.
2. Из какого РЕСУРСА: имя/ID ресурса (RT_BITMAP? RT_RCDATA с PNG? отдельные .ico?),
   как он объявлен в .rc файле NPP. Дай реальные resource id/имена.
3. Разные наборы иконки (standard vs Fluent vs filled) — какой грузится по умолчанию и
   меняет ли это API/ресурс.
4. bpp/формат: 24bpp BMP с маской, или 32bpp с альфой? (важно для probe — какой LoadImage
   flag и какой DIB layout воспроизводить.)
