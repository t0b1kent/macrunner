Codex — уточнение спека по disabled-иконкам тулбара (к промту STOP-TOOLBAR-
REGRESSION). Это ГЛАВНОЕ требование по иконкам, сделай ИМЕННО так.

ТЕКУЩЕЕ (неправильно): мы сделали disabled-иконки ВСЕГДА цветными (workaround
"draw from default imagelist"). Это убирает различие активная/неактивная. (А сейчас
ещё и регресс — пустые.)

ПРАВИЛЬНО (как настоящий Windows / CrossOver):
- ENABLED (активная) кнопка → ПОЛНОЦВЕТНАЯ иконка.
- DISABLED (неактивная) кнопка → СЕРЫЙ затенённый силуэт (desaturate + чуть тусклее),
  рисунок ВИДЕН, но серый. НЕ пустой квадрат, НЕ полноцвет.
- ПЕРЕХОД состояния динамический: на пустом новом доке Save/SaveAll/Undo/Redo/macro =
  неактивны (серые). После правки документа Save и Undo становятся активны → СТАНОВЯТСЯ
  ЦВЕТНЫМИ. comctl32 перерисовывает кнопку при смене TBSTATE_ENABLED.

ТЕХНИЧЕСКИ:
- comctl32 toolbar уже различает состояние (TBSTATE_ENABLED → CDIS_DISABLED в
  TOOLBAR_DrawImage). Enabled путь = обычный ImageList_Draw (цвет) — он работает.
- Disabled путь должен давать СЕРЫЙ силуэт из default-иконки: отрисуй default image,
  GRAYSCALE его (luminance + лёгкое затемнение/alpha), и нарисуй. Прошлый ILS_SATURATE
  давал пусто, т.к. брал из ПУСТОЙ маски — бери из РЕАЛЬНО отрисованной default-иконки
  (как твой sentinel-DIB подход 14:04, но с правильной непрозрачностью → серый
  виден, не прозрачный, не полноцвет).
- НЕ "always colorful". Различие активн/неактивн — обязательно.

ПРОВЕРКА (строгий gate, реальное окно):
- Пустой док: disabled-слоты = серый силуэт (есть контент, low saturation), НЕ пусто.
- Введи текст → Save/Undo слоты становятся ЦВЕТНЫМИ (saturation растёт). Сравни кадр
  до/после правки: переход disabled→active виден.
- Enabled-иконки всегда цветные. Тулбар без пустых слотов (не регрессируй).
