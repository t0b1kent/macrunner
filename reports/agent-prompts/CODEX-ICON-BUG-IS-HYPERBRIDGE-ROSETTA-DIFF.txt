Codex — РЕШАЮЩИЙ вывод из stock-теста: баг иконок НЕ в comctl32/Wine, а в HyperBridge.

ДОКАЗАТЕЛЬСТВО:
- Чистый upstream Wine 11.0 comctl32+toolbar (байт-в-байт сток) на нашем движке →
  иконки = ЧЁРНЫЕ КВАДРАТЫ (хуже, чем с нашими патчами — патчи были band-aids).
- Тот же стоковый Wine + Rosetta (CrossOver) → иконки ПРАВИЛЬНЫЕ.
- winemac.drv (хостовый ARM64 граф-драйвер) у нас и у CrossOver похож → CrossOver на
  нём рисует правильно → ХОСТОВЫЙ путь исправен.
- Единственная разница: гостевой x86 через Rosetta (ок) vs HyperBridge (чёрное).
ВЫВОД: HyperBridge неправильно транслирует x86-инструкции в пути отрисовки иконок/
DIB-blit → пиксели обнуляются (чёрный). Это класс 9 фундаментальных багов (декодер/
JIT), вероятно баг №10. Месяцы comctl32-патчей лечили не тот слой.

ШАГ A — подтверди слой (быстро):
- Собери со СТОКОВЫМ win32u тоже (у тебя diff в reports/stock-user32-win32u-step1).
  Сток comctl32 + сток win32u → всё равно чёрное? → Wine-исходник чист, баг в
  HyperBridge (трансляция). Подтверждает вывод.

ШАГ B — найди инструкцию (Rosetta как differential-oracle, твоя сильная сторона):
- Изолируй путь отрисовки иконки: PE-ресурс → DIB → blit/alpha-blend → surface.
  Чёрные пиксели = blit записал нули вместо данных иконки. Подозрение: SIMD/memory
  инструкция (movdqa/pmullw/punpck/alpha-math) или mask-копирование.
- Дифференциал: один и тот же x86 blit-код прогнать под Rosetta (правильный вывод)
  и под HyperBridge (чёрный) → сравнить байты выходного буфера → бисекция до
  КОНКРЕТНОЙ инструкции, которую HyperBridge транслирует неверно.
  * Практично: маленький x86 тест (или трасса реального blit) с дампом входного и
    выходного буфера. Запусти его через CrossOver/Rosetta (эталон) и через нас.
  * Где расходятся байты → там инструкция. Сравни с Intel SDM, как в багах №1-9.
- Фикс в HyperBridge decoder/lifter/JIT (как 9 предыдущих). Family audit: вся семья
  инструкции, не один байт.

ВАЖНО — НЕ возвращай comctl32 патчи (принцип):
- Корректный транслятор обязан гонять СТОКОВЫЙ Wine без правок (CrossOver гоняет сток
  через Rosetta — работает). Наши рендеринг-патчи = КОСТЫЛИ вокруг багов HyperBridge,
  нарушают Zeroth Principle.
- ОСТАВЬ стоковый Wine (сейчас чёрные иконки — норм, это dev/validation состояние).
  Стоковый Wine = ЦЕЛЬ ВАЛИДАЦИИ: чини HyperBridge, пока СТОК не нарисует правильно
  (как CrossOver). Это форсирует настоящий root-fix, а не маскировку.
- Что НЕ трогать: ntdll/* (loader/signal/macrunner_hb/virtual) = легитимная
  HyperBridge↔Wine интеграция; winemac.drv = хостовый драйвер. Это не костыли.
- После фикса HyperBridge: ВЫКИНУТЬ все 469+117 рендеринг-патчей comctl32/user32/
  win32u к стоку (ноль расхождений с upstream, упрощение).
- Журнал: вердикт "stock comctl32 → black on HyperBridge → bug below Wine, in
  translator" + найденная инструкция когда найдёшь.
- Это твоя коренная экспертиза (декодер/опкоды), не визуал. Verify: реальное окно +
  Rosetta-эталон совпадает по байтам.

ЦЕННОСТЬ: один translator-фикс закроет иконки ВЕЗДЕ (тулбар/папки/tab/везде где DIB-
blit), и для ВСЕХ будущих приложений. Это корень, а не косметика.

=== ЭТАЛОНЫ ИЗ ИНТЕРНЕТА (как ПРАВИЛЬНО транслировать — open source) ===
Прямого решения для HyperBridge нет (он наш), но есть reference-реализации x86→ARM,
с которыми сверять найденную инструкцию:
- **sse2neon** (github.com/DLTcollab/sse2neon) — корректный перевод КАЖДОГО SSE-
  интринсика в ARM NEON, хорошо оттестирован. Нашёл подозрительную инструкцию →
  сверь свою трансляцию с тем, как sse2neon делает NEON-эквивалент.
- **FEX-Emu** (github.com/FEX-Emu/FEX) и **box64** — открытые x86→ARM JIT. Их
  обработка blit/SIMD = reference-correct. Глянь их issue-трекеры по инструкции.
ИЗВЕСТНЫЕ ГРАБЛИ SSE→NEON (вероятные кандидаты на чёрные пиксели):
- **packuswb** (pack с unsigned saturation) — поведение saturation у SSE и NEON
  РАЗНОЕ; частая в alpha-blend. Если HyperBridge врёт saturation → битые пиксели.
- **pmullw / pmaddwd** (умножение в alpha-math), **punpcklbw/punpckhbw** (распаковка
  байт→слов в премультипликации), **psrlw** (сдвиг).
- **pmovmskb** — у NEON нет прямого эквивалента, требует редизайна (частый источник
  багов перевода).
- IEEE-754 расхождения в float-пути (если иконки через float alpha).
СТРАТЕГИЯ: blit/AlphaBlend премультиплицирует alpha через SSE2 (pmullw/psrlw/
packuswb/punpck). Чёрные пиксели = одна из них даёт нули. Начни проверку с packuswb
saturation и punpck — сверь с sse2neon/Intel SDM.
