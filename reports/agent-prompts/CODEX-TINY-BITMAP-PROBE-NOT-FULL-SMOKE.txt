!!! ОБНОВЛЕНО по research Cline (reports/engine-audit/NPP-TOOLBAR-RESOURCE-FINDINGS.md):
МОДЕРН-ТУЛБАР NPP грузит иконки как ICON-ресурсы IDI_* (32bpp), НЕ RT_BITMAP. Точный путь:
ImageList_Create(cx,cy,ILC_COLOR32|ILC_MASK) + LoadImage(IMAGE_ICON, IDI_*) + ImageList_AddIcon
+ TB_SETIMAGELIST. Resource id: IDI_NEW_ICON=201 ... IDI_VIEW_DOCLIST_ICON=247 (set2 301-347,
dark 251-297, dark2 351-397). RT_BITMAP 0x05ed = НЕ тот путь (это legacy TB_STANDARD).
БЕЙ ICON-путь первым — иначе probe даст ложный «всё цветное».

Probe должен (точный ICON-путь):
1. Открыть notepad++.exe как модуль с ресурсами:
   LoadLibraryExW(npp_path, NULL, LOAD_LIBRARY_AS_DATAFILE) — путь как аргумент.
2. Перечислить реальные ICON-ресурсы (НЕ хардкодить один id):
   - EnumResourceNamesW(h, RT_GROUP_ICON, ...) — все group-icon ресурсы; ИЛИ перебрать
     известный диапазон IDI_* 201..247 (и 301..347 / 251..297, если активна тема/набор).
3. Для каждого ICON-ресурса воспроизвести ИМЕННО modern producer-путь:
   - hicon = LoadImageW(h, MAKEINTRESOURCEW(id), IMAGE_ICON, cx, cy, LR_DEFAULTCOLOR)
     (cx=cy=16 или реальный iconSize).
   - GetIconInfo(hicon, &ii) → ii.hbmColor (32bpp) и ii.hbmMask.
   - GetObjectW(ii.hbmColor, ...) — w/h/bpp; GetDIBits hbmColor → 32bpp top-down → посчитать
     colorful / nonwhite / black. Стадия = icon_color_bits.
   - Затем реальный comctl32-путь: ImageList_Create(cx,cy,ILC_COLOR32|ILC_MASK,..) →
     ImageList_AddIcon(himl, hicon) → ImageList_GetIcon / ImageList_Draw в memory DC →
     GetDIBits → стадия = imagelist_after_add. Это совпадает с add_dib_bits boundary.
   - Печать: MR_ICON_PROBE resid=<id> hicon=<h> w=<> h=<> bpp=<> colorful=<> nonwhite=<>
     black=<> stage=<icon_color_bits|imagelist_after_add>
   - Доп. (опц.): legacy путь LoadImage(IMAGE_BITMAP, IDR_*, LR_LOADMAP3DCOLORS|
     LR_LOADTRANSPARENT) + GetDIBits — только если modern путь окажется цветным.
4. Acceptance probe:
   - попадает в ICON-ресурсы IDI_* КАЖДЫЙ запуск;
   - печатает icon_color_bits и imagelist_after_add stats;
   - завершается за секунды; НЕ зависит от FULL_UI_READY / создания toolbar-окна.

=== РЕШЕНИЕ ПО РЕЗУЛЬТАТУ (слой за один прогон) ===
- icon_color_bits ЦВЕТНЫЕ, imagelist_after_add ЧЁРНЫЕ → root = host comctl32-ingest /
  win32u GetDIBits/DIBSection readback → фикс host-win32u/imagelist boundary.
- icon_color_bits УЖЕ ЧЁРНЫЕ → root = ICON resource load / guest decode / HyperBridge
  memory-copy при распаковке иконки → привязать к PC/опкоду/memcopy-семье, добить весь
  стек (decode→IR→lift→interp→jit→тесты→oracle/FileCheck), как REP MOVS/CMPS/LODS.
- probe ЦВЕТНОЙ на обеих стадиях, но NPP toolbar всё равно чёрный → root ПОЗЖЕ (draw/
  themed v6 / present) → вернуться к comctl32 ingest/draw с этим знанием.
