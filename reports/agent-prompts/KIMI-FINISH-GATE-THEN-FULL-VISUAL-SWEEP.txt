ШАГ 1 — ДОБИТЬ VISUAL GATE (последние 5%, ты не успел из-за токенов)
============================================================
Ты закалил scripts/visual-gate-notepad.sh правильно (канонический run-notepad-x64.sh
+ window-crop через cg_window_probe.swift/cg_window_capture.swift). НО прогон падает:
оконный пробник возвращает "No Notepad++ window found" и убивает процесс ДО захвата.
Я воспроизвёл: даже вручную `swift cg_window_probe.swift notepad` сразу после launch
видит 0 окон — нет retry-ожидания появления окна Wine.

Почини:
- Пробник должен ЖДАТЬ окно в retry-loop (напр. до 30-40с, шаг 2с), а не один раз.
- Проверь как окно Wine реально светится в CGWindowList: owner может быть не
  "notepad" а имя процесса/"Wine" — match по owner ИЛИ по title ("Notepad++",
  "new ", "Save As"). Сейчас фильтр слишком узкий → 0 окон.
- Окно появляется ~через сколько? Канонический раннер держит app живым
  (alive_after_18s=1 подтверждено) — значит окно ЕСТЬ, пробник его не находит.

Валидация (обязательно — gate без прогона не принят):
- Прогони gate на ТЕКУЩЕМ билде → reports/visual-regression/notepad-gate/RESULT.md
  + RESULT.json + аннотированный кроп.
- Сверь вердикт с реальностью на скриншоте. Если тулбар цветной — toolbar PASS;
  если разделителей колонок нет — header FAIL и т.д. Не совпало → чини пороги/регионы.

ШАГ 2 — ПОЛНЫЙ ВИЗУАЛЬНЫЙ SWEEP (один проход, ВСЕ дефекты)
============================================================
Принцип batch (AGENTS.md): НЕ по одному дефекту. Пройди ВСЕ поверхности Notepad++
за один заход, захвати каждую (тем же window-crop), классифицируй КАЖДЫЙ визуальный
дефект → один полный punch-list. Чтобы Codex закрыл Notepad++ зелёным пачкой.

Поверхности для обхода (каждую — скриншот + анализ):
1. Главное окно: caption + кнопки min/max/close (Marlett), меню-бар, тулбар,
   вкладки (tabs), editor area, статус-бар внизу, скроллбары (верт+гориз).
2. Диалоги: Save As, Open, Find/Replace (Search→Replace), Go to, Preferences
   (Settings→Preferences — много вкладок/контролов), About, Run.
3. В каждом диалоге: заголовки колонок ListView (SysHeader32 divider-линии —
   пользователь уже заметил их отсутствие в Save As), дерево папок (TreeView),
   иконки (folder ICO), кнопки, чекбоксы, комбобоксы, edit-поля, групбоксы (рамки).

Для КАЖДОГО найденного дефекта — запись в punch-list:
  Surface | Element | Симптом | Семья (из GUI catalog) | Severity | file:line гипотеза | Confidence
Используй GUI catalog из AGENTS.md (Marlett / GetSysColor / comctl32 header/tab/
scrollbar / shell32 icons / fonts/tofu / DIB-конверсия). Новые классы → отметь.

Известные открытые на сейчас (подтверди статус, не пропусти):
