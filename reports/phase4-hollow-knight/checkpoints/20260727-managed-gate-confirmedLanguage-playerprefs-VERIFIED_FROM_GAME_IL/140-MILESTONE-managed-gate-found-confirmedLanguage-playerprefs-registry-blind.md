# 140 — MILESTONE: спросили у самой игры — она ждёт флаг, которого некому поставить; а меню показано из-за нашего же бага с реестром

Продолжает [[139-MILESTONE-FIRST-VISIBLE-PIXEL-hollow-knight-language-menu-onscreen]].

> [!important] Главное
> Неделю мы выводили намерения Hollow Knight снаружи — по маркерам, по диффу с оракулом, по состоянию процесса. Managed-сборки игры всё это время лежали в дереве. **45 минут декомпиляции дали ответ с токенами:** игра крутит `while (!confirmedLanguage) yield return null;`, а меню языка вообще показано потому, что **наш нативный PlayerPrefs не видит реестр префикса**.

## Гейт — из IL, а не по догадке

```
StartManager.<Start>d__25.MoveNext     token 0x060041d2, опрос на IL_00da
    while (!confirmedLanguage) yield return null;
поле confirmedLanguage                 token 0x04000DE2
```

Это **предикат опроса, который никогда не становится истинным**, а не блокирующее ожидание. Отсюда и вся путаница: тред живой, грузит CPU, не двигается. Мы искали, «где он висит», а он не висел — он каждый кадр проверял флаг.

Ставит флаг ровно одно место:

```
public void StartManager::ConfirmLanguage()    token 0x06000e6c, RVA 0x50d70
```

и у него **ноль IL-вызывающих** — метод достижим только кликом по UI. Ничто внутри игры его не позовёт. `SetLanguage("EN")` перед ним не нужен.

## Почему меню вообще на экране — и вот это уже наш баг

`PlayerPrefs.GetInt("GameLangSet", 0)` возвращает **0, хотя значение в реестре префикса есть**. `PlayerPrefs.HasKey("M2H_lastLanguage")` тоже промахивается. Два независимых managed-чтения падают на том же содержимом реестра, которое windows-оракул читает нормально на той же сборке игры — отсюда `Loaded system language` у нас против `Loaded saved language code 'EN'` у него.

**Значит ветка saved/system никогда не была переключателем.** run15 пошёл системной веткой и встал у той же стены — версию про «оракульный шаблон блокирует загрузку» это опровергло, и хорошо, что опровергло данными, а не спором.

Цепочка целиком:

> PlayerPrefs не читает сохранённый язык → игра считает, что язык не выбран → показывает меню → паркуется на `while (!confirmedLanguage)` → ждёт клика, которого некому доставить.

Это связывает всё, что мы копали сутки: и меню на скриншоте из [[139-MILESTONE-FIRST-VISIBLE-PIXEL-hollow-knight-language-menu-onscreen]], и «остановку managed-бутстрапа», и дыру с вводом.

## Метод

Отдельный оффлайновый лайн на Kimi, без прогонного слота, территория — только сборки игры на чтение. Жёсткий гейт в промте: **цитировать IL или восстановленный C#**, утверждение про поток управления без тела метода — догадка. В чекпойнте лежат 27 IL-дампов, так что каждое утверждение перепроверяемо по байткоду.

Параллельно движковый лайн отозвал собственные показания по матрицам (классификация зависела от раскладки константного буфера, а не от данных) и перед тратой слота статически проверил, что все 23 managed-символа его пробника существуют в сборке.

> [!warning] Чего майлстоун НЕ утверждает
> Не исправлено **ничего**. Игра по-прежнему стоит на меню. Актуатор гейт снимет, но это обход, а не фикс. Настоящий дефект — нативное чтение реестра — только назван, не починен.

## Два пути, и это не альтернативы

1. **Разблокировка:** `mono_runtime_invoke` по токену `0x06000e6c` через существующий актуатор `tools/hk_language_observer/`. Снимает гейт и показывает следующую стену.
2. **Фикс:** починить нативный PlayerPrefs → реестр. Тогда игра прочитает свой язык, меню не покажет и загрузится как оракул.
