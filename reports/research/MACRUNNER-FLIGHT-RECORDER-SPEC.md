# MacRunner Flight Recorder Specification (JSONL Format)

This document specifies the format, schemas, and usage rules for the MacRunner Flight Recorder (`MACRUNNER_FLIGHT_RECORDER=1`). The flight recorder is designed to capture precise low-level runtime events from the CPU translator (HyperBridge), the Wine compatibility layers, memory managers, and graphic gates without altering application semantics.

## Schema Overview

All captured records are logged to a file named `flight.jsonl`. Each event is structured as a single JSON line terminated by a newline (`\n`). The general event structure is:

```json
{"ts": <timestamp_ns>, "pid": <process_id>, "tid": <thread_id>, "ev": "<event_type>", <event_specific_fields>}
```

### Common Fields
- `ts`: Timestamp in nanoseconds since an arbitrary but stable epoch (e.g., system startup).
- `pid`: Integer process ID.
- `tid`: Integer thread ID.
- `ev`: String identifier for the event type.

---

## Required Event Types

### 1. Process and Thread Lifecycle
- `run_start`: Emitted when the MacRunner process launches.
  - `cmdline`: (string) Full command line string.
- `run_end`: Emitted before the runner process exits.
  - `exit_code`: (int) Final exit status.
- `process_create`: Emitted when a new child process is spawned.
  - `new_pid`: (int) Process ID of the child.
  - `image_path`: (string) Path to the binary executable.
- `thread_create`: Emitted when a new execution thread starts.
  - `new_tid`: (int) Target thread ID.
  - `entry_point`: (hex string or int) Memory address of the entry function.
- `thread_exit`: Emitted when a thread terminates.
  - `exit_code`: (int) Thread exit code.

### 2. Module Mapping
- `module_map`: Emitted when a PE or ELF binary is mapped into memory.
  - `base_addr`: (int/hex) Load address.
  - `size`: (int) Memory size of the module in bytes.
  - `name`: (string) Lowercase file name.
  - `arch`: (string) E.g., `"x86_64"`, `"i386"`, `"arm64ec"`, `"arm64"`.
- `module_unmap`: Emitted when a module is unmapped.
  - `base_addr`: (int/hex) Unmap base address.

### 3. Memory & Code Translation
- `virtual_alloc`: Virtual memory allocation.
  - `addr`: (int/hex) Base address.
  - `size`: (int) Allocation size.
  - `protect`: (int) Win32 memory protection flags (e.g., PAGE_EXECUTE_READWRITE = 0x40).
- `virtual_protect`: Memory protection modifications.
  - `addr`: (int/hex) Target address.
  - `size`: (int) Modified block size.
  - `new_protect`: (int) New protection flags.
  - `old_protect`: (int) Previous protection flags.
- `flush_icache`: Instruction cache invalidation request.
  - `addr`: (int/hex) Target address.
  - `size`: (int) Flush size.
- `exec_block`: Execution checkpoint of a translated block.
  - `pc`: (int/hex) guest program counter.
- `tb_generate`: Translation block generated by JIT.
  - `pc`: (int/hex) Start guest address.
  - `size`: (int) Size of the guest block.
- `tb_invalidate`: Translation block invalidated due to SMC or page protection changes.
  - `pc`: (int/hex) Target guest address.
- `smc_write`: Self-modifying code write detected.
  - `addr`: (int/hex) Target modified address.
  - `val`: (int) The written byte/word/dword value.

### 4. Cross-Arch Callbacks
- `arm64ec_callback`: Emitted during transition boundaries between ARM64 and x64 execution spaces.
  - `target`: (int/hex) Destination address.
  - `caller`: (int/hex) Caller return address.
  - `argc`: (int) Argument count.
  - `x0` .. `x7`: (int) Argument registers values.
  - `stack_args`: (array of ints) Arguments passed via the execution stack.

### 5. Synchronization Objects
- `wait_object`: A thread enters a wait state on a kernel object.
  - `object_id`: (int) Stable unique identifier of the kernel object.
  - `handle`: (int) Raw Win32 handle.
  - `timeout`: (int) Timeout value.
- `set_event`: Wake or signal event object.
  - `object_id`: (int) Stable unique identifier.
  - `handle`: (int) Raw handle.
- `reset_event`: Clear signal state of an event.
  - `object_id`: (int) Stable unique identifier.
  - `handle`: (int) Raw handle.
- `release_semaphore`: Signal release count on a semaphore.
  - `object_id`: (int) Stable unique identifier.
  - `count`: (int) Release count value.

> [!IMPORTANT]
> **Object ID Rule**: Every kernel object must be assigned one stable, unique integer ID (`object_id`) at its creation. This ID is preserved across DuplicateHandle calls and process inheritance boundaries. Analyzers must use this `object_id` rather than raw Win32 handles to resolve signals and deadlocks, as handles can be recycled.

### 6. Windowing and UI
- `create_window`: Window instance creation.
  - `hwnd`: (int/hex) Raw window handle.
  - `class_name`: (string) Window class name.
  - `atom`: (int) Registered window class atom.
- `register_class`: Window class registration.
  - `class_name`: (string) Name of the class.
  - `atom`: (int) Registered atom identifier.
  - `instance`: (int/hex) Associated HINSTANCE.
- `ntusercreatewnd_server`: Server-side NtUserCreateWindowEx gateway callback.
  - `hwnd`: (int/hex) Allocated HWND.
  - `class_name`: (string) Resolved class name.

### 7. Graphics (D3D)
- `d3d_entry`: Call into a DirectX interface function.
  - `api`: (string) Name of the function (e.g. `CreateDXGIFactory`, `D3D11CreateDevice`, `CreateSwapChain`, `Present`).

### 8. Diagnostics
- `runtime_fault`: Native CPU or Wine exception.
  - `code`: (int/hex) NTSTATUS code (e.g. `0xC0000005` for access violation).
  - `address`: (int/hex) Memory address of faulting instruction.
- `assert_fail`: Assert statement failed in internal components.
  - `expr`: (string) The assert expression that evaluated to false.
  - `file`: (string) File path containing the failure.
  - `line`: (int) Line number.

## Worked Examples

### 1. Wait/Wake Pair Event Sequence
In this example, Thread 0x24 enters a wait on a synchronization Event (ID 42). Thread 0x2c subsequently signals it.

```json
{"ts":10000000,"pid":1234,"tid":36,"ev":"wait_object","object_id":42,"handle":48,"timeout":-1}
{"ts":10005000,"pid":1234,"tid":44,"ev":"set_event","object_id":42,"handle":12}
```

### 2. ARM64EC High-Argc Callback
Transition from ARM64EC to x64. The signature has 10 arguments. Registers `x0` through `x7` hold the first 8 arguments, and the remaining 2 are fetched from the thread stack.

```json
{"ts":20000000,"pid":1234,"tid":36,"ev":"arm64ec_callback","target":5368717312,"caller":5368721408,"argc":10,"x0":100,"x1":200,"x2":300,"x3":400,"x4":500,"x5":600,"x6":700,"x7":800,"stack_args":[900,1000]}
```

### 3. SMC Stale TB (Self-Modifying Code execution of stale Translation Block)
An application writes to instruction memory (SMC write) but does not immediately call `flush_icache` or `virtual_protect` to mark pages writeable. As a result, JIT continues running a stale block instead of invalidating and regenerating.

```json
{"ts":30000000,"pid":1234,"tid":36,"ev":"tb_generate","pc":4294967296,"size":64}
{"ts":30010000,"pid":1234,"tid":36,"ev":"smc_write","addr":4294967300,"val":144}
{"ts":30020000,"pid":1234,"tid":36,"ev":"exec_block","pc":4294967296}
```

### 4. D3D11 Gate Loading & Present Sequence
A successful Direct3D initialization sequence starting from loading D3D libraries up to swapping frames.

```json
{"ts":40000000,"pid":1234,"tid":36,"ev":"module_map","base_addr":140737488355328,"size":2097152,"name":"d3d11.dll","arch":"x86_64"}
{"ts":40010000,"pid":1234,"tid":36,"ev":"module_map","base_addr":140737486258176,"size":1048576,"name":"dxgi.dll","arch":"x86_64"}
{"ts":40020000,"pid":1234,"tid":36,"ev":"d3d_entry","api":"CreateDXGIFactory"}
{"ts":40030000,"pid":1234,"tid":36,"ev":"d3d_entry","api":"D3D11CreateDevice"}
{"ts":40040000,"pid":1234,"tid":36,"ev":"d3d_entry","api":"CreateSwapChain"}
{"ts":40050000,"pid":1234,"tid":36,"ev":"d3d_entry","api":"Present"}
```

### 5. PE32/WOW64 Handoff
Emits events showing that the system loaded `wow64cpu.dll`, loaded `btcpu.dll` (or WOW64 CPU simulator), initialized the process, thread, and began WOW64 simulation.

```json
{"ts":50000000,"pid":1234,"tid":36,"ev":"module_map","base_addr":5368709120,"size":524288,"name":"wow64cpu.dll","arch":"x86_64"}
{"ts":50010000,"pid":1234,"tid":36,"ev":"module_map","base_addr":5369233408,"size":524288,"name":"btcpu.dll","arch":"x86_64"}
{"ts":50020000,"pid":1234,"tid":36,"ev":"virtual_alloc","addr":4096,"size":4096,"protect":64}
{"ts":50030000,"pid":1234,"tid":36,"ev":"exec_block","pc":5368709200}
```
