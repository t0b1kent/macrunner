# Разбор Prism по двоичным файлам — 2026-08-07

Снято с живой Windows 11 ARM64 (build 26200.8875) в виртуалке: карта системы, зонд памяти
работающей игры и таблицы экспорта самих файлов. Инструменты: `tools/prism-collect.ps1`,
`tools/prism-probe-hk.ps1`, `tools/prism-extract.ps1`, `tools/prism-parse.py`.

**Разделение фактов и оценок.** Всё в разделах 1–4 — прочитано из файлов и из живого процесса.
Раздел 5 — что из этого следует для нас, и там оценки помечены.

---

## 1. ФАКТ: стена с `MEM_FREE` — наш пропуск, а не цена эмуляции

Зонд `VirtualQueryEx` внутри образов живого Hollow Knight под настоящим Prism:

```
Hollow Knight.exe   база=0x7FF7F9500000   MEM_COMMIT  MEM_IMAGE  EXECUTE_READ
ntdll.dll           база=0x7FFF486D0000   MEM_COMMIT  MEM_IMAGE  EXECUTE_READ
xtajit64se.dll      база=0x7FFF479C0000   MEM_COMMIT  MEM_IMAGE  EXECUTE_READ
UnityPlayer.dll     34 725 888 байт — в списке загрузчика
всего модулей: 88
```

У нас на том же запросе — `база=0, MEM_FREE, NOACCESS`, при живой игре, грузящей объекты.

**Вывод:** Prism заводит гостевые образы в учёте виртуальной памяти полностью. Обе наши слепые
проверки — список загрузчика и опрос отображений — промахиваются по одной причине: образы никто
не регистрирует.

## 2. ФАКТ: контракт x86 — ровно 25 функций `BTCpu*`

`xtajit.dll` (x86-эмулятор) экспортирует именно их. Это буквальный интерфейс, который загрузчик
Windows ждёт от эмулятора процессора:

```
BTCpuProcessInit      BTCpuProcessTerm       BTCpuThreadInit      BTCpuThreadTerm
BTCpuSimulate         BTCpuResetToConsistentState                 BTCpuGetBopCode
BTCpuNotifyMemoryAlloc / Free / Protect / Dirty
BTCpuNotifyMapViewOfSection      BTCpuNotifyUnmapViewOfSection
BTCpuFlushInstructionCache2      BTCpuFlushInstructionCacheHeavy
BTCpuNotifyReadFile   BTCpuNotifyAffinityChange
BTCpuNotifyProcessExecuteFlagsChange          BTCpuSuspendLocalThread
BTCpuOptimizeChpeImportThunks    BTCpuUseChpeFile
BTCpuCfgDispatchControl          BTCpuIsProcessorFeaturePresent
BTCpuResetFloatingPoint          BTCpuUpdateProcessorInformation
```

**`BTCpuNotifyMapViewOfSection` — вот чем Prism узнаёт об отображении образа.** Наша стена из
раздела 1 названа поимённо.

Наш `xtajit.spec` содержит 21 функцию. **Отсутствуют семь:**
`BTCpuCfgDispatchControl`, `BTCpuNotifyAffinityChange`,
`BTCpuNotifyProcessExecuteFlagsChange`, `BTCpuOptimizeChpeImportThunks`,
`BTCpuResetFloatingPoint`, `BTCpuSuspendLocalThread`, `BTCpuUseChpeFile`.

## 3. ФАКТ: у x64-эмулятора экспорта НЕТ ВООБЩЕ

Проверено разбором каталога экспорта напрямую, а не отсутствием вывода:

```
xtajit64.dll    каталог по RVA 0x1542B0, размер 136 — функций 0, имён 0
xtajit64se.dll  каталог по RVA 0x1B96D0            — функций 0, имён 0
```

Каталог существует и содержит только имя модуля. **То есть x64-эмуляция на ARM64 подключается
НЕ через экспортируемый контракт, в отличие от x86.** Чем именно — не установлено; кандидаты:
секция `.hexpthk` (ARM64EC-заглушки, есть в обоих), точка входа PE, или вызов из `wow64.dll` по
иному механизму. **Нужен разбор, это открытый вопрос.**

Наш `xtajit64.spec` экспортирует четыре функции с именами `BTCpu64*` — такой схемы нет ни в
x86-контракте, ни в их x64-модуле.

## 4. ФАКТ: трансляторов пять, и есть отдельные AOT-компиляторы

```
xtajit.dll      1 032 104   v10.0.26100.8875     xtac.exe       1 006 832
xtajit64.dll    1 455 208   v10.0.26100.8737     xtac64.exe     1 090 032
xtajit64se.dll  1 880 328   v10.0.26100.8737     xtac64se.exe   1 393 176
xtajitf.dll     1 439 696   v10.0.26100.8875     XtaCache.exe      73 520
xtajitse.dll    1 458 792   v10.0.26100.8875
```

Игра грузит **`xtajit64se.dll`** — не тот модуль, что реализуем мы. Пары `64`/`64se` имеют
версию `.8737`, остальные `.8875`: обновляются раздельно.

`xtajit`, `xtajitse`, `xtajitf` экспортируют **одинаковые 25 функций** — значит это варианты
одного транслятора, а не разные роли.

**`xtac*.exe` — отдельные исполняемые AOT-компиляторы.** У нас такого класса нет вовсе: только
JIT в процессе. Их запускает служба `XtaCache` (`LaunchProtected=2`, то есть защищённый процесс).

Кеш `C:\WINDOWS\XtaCache` на момент съёмки **пуст** — 0 файлов. Формат не установлен.

## 5. Что из этого следует — ОЦЕНКИ, ранжированные

1. **Регистрировать гостевые образы в учёте VM.** Единственный пункт, где механизм-донор
   назван поимённо (`BTCpuNotifyMapViewOfSection`), а наш дефект измерен. Ожидаемый эффект:
   прозревают обе слепые проверки, и диагностика, сегодня молчащая под условием «модуль
   найден», начинает печатать. Величина не оценивается — **нужен замер**.
2. **Разобрать, как подключается x64-эмулятор** (раздел 3). Пока неизвестно, мы воспроизводим
   контракт по образцу x86, а он для x64 не тот. Это может объяснять больше, чем кажется.
3. **Семь недостающих функций** из раздела 2 — дописать. Дёшево, но эффект неизвестен: часть
   может никогда не вызываться.
4. **AOT-компиляция отдельным процессом** — самое дальнее и самое дорогое. Отмечено как
   существующее у них и отсутствующее у нас, не более.
