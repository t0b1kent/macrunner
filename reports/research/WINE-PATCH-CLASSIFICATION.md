# Разметка наших правок Wine — что куда и зачем

Составлено 2026-08-04 сравнением нашего дерева с чистым Wine 11.14
(ветка `upstream/wine-11.14`, коммит `2bc8b9ab`). Обновляется той же командой при новом релизе.

## Зачем это

До сих пор обновление Wine было лотереей: у нас 1248 меток в одном `loader.c`, дерево взято
слепком на 11.0 и не связано с upstream. «Перейти на новую версию» означало снести полгода работы
и узнать, что именно потеряно, через неделю на прогонах.

Разметка отвечает на вопрос, какие правки при обновлении **выбрасываются**, какие **наши
навсегда**, и какие **надо каждый раз проверять** — вдруг там уже починили.

## Итог

## Что делать с каждым родом

**Диагностика (74%, 16 562 строки).** Трассировка, счётчики, переписи, дампы. При обновлении
переносится механически или **выбрасывается вовсе**: приборы ставятся под задачу и живут, пока
задача не закрыта. Половину из них можно удалить уже сейчас — они от закрытых расследований.
Ищется по: `TRACE(`, `ERR(`, `fprintf`, `macrunner_signal_writef`, `_census`, `_meter`, `_probe`.

**Наша платформа (4%, 809 строк).** Обходы того, чего у upstream нет и не будет: macOS стирает
`x18` при переключении контекста, свой композитор, `MAP_JIT`, вызовы Mach, свой стек сигналов.
**Наше навсегда**, переносится всегда, upstream это не починит никогда.
Ищется по: `x18`, `__APPLE__`, `Darwin`, `mach_`, `winemac`, `GA_ROOT`, `MAP_JIT`, `pthread_jit`.

**Связка с транслятором (4%, 959 строк).** Точки, где Wine зовёт наш движок. У upstream
отсутствует по определению — там нет нашего транслятора. Переносится всегда.
Ищется по: `macrunner_hb_`, `hb_jit`, `hb_memory`, `hb_runtime`.

**Прочее (18%, 4 083 строки) — ЕДИНСТВЕННОЕ, что требует ревизии при каждом обновлении.**
Это починки, которые могли быть сделаны и у них. Сосредоточено в трёх файлах:
`unix/virtual.c` (1345), `unix/loader.c` (919), `resource.c` (166 — весь файл в этой категории).
Порядок ревизии: взять кусок, найти соответствующее место в новом upstream, проверить, не решена
ли задача там. Решена — выбросить наше.

## Как обновить разметку при новом релизе Wine

```bash
# 1. положить новый релиз в ветку upstream (см. README-UPSTREAM.md в ней)
# 2. пересчитать:
cd <корень>
python3 <скрипт из .tmp/research/, сохранён в истории коммита>
```

Разметка построена автоматически по признакам в тексте кусков, а не вручную. Значит она
воспроизводима и не устаревает: перезапустил — получил актуальную картину.

## Честная граница метода

Классификация по признакам в тексте, а не по смыслу. Кусок, где диагностика перемешана с
починкой, попадёт в «диагностику» целиком. Для оценки масштаба и для планирования обновления
этого достаточно; для решения «выбросить или оставить» конкретный кусок — надо смотреть глазами.

Категория «прочее» намеренно широкая: лучше проверить лишнее, чем пропустить починку, которая
уже есть в upstream.
