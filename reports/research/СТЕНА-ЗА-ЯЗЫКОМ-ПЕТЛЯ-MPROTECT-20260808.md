# Стена за экраном языка: петля mprotect — 08.08.2026

Продолжение `СТЕНА-ЗА-ЭКРАНОМ-ЯЗЫКА-20260807.md`. Прогон
`laneA-профиль-эталон-меню-a1-try1-223253`, дист `dist-0806-floor26-ЭКРАН-ЯЗЫКА`
(`ntdll 5746c84acb41b6d4`), гейт `MACRUNNER_HB_TRACE_HOST_EXEC=1`.

Лог вырос до 8,3 ГБ за двенадцать минут; трасса вырезана, выжимка рядом в
`выжимка-mprotect.txt`.

## Замер

```
24 490 031   base=0xebb4b8000  size=4000  requested=0x5 → final=0x5  x64_guest=0
       52    0xebde50000
       36    0xeb3cf8000
```

**24,5 миллиона вызовов `mprotect` на ОДНУ страницу.** Все прочие адреса вместе — меньше
пятисот. Каждый вызов просит `r-x`, получает `r-x`, возвращает успех — и отказ повторяется.

Формы по всему прогону:

```
24 490 820   0x5 → 0x5   guest=0
      1910   0x7 → 0x3   guest=0
       724   0x1 → 0x1   guest=1
       624   0x7 → 0x3   guest=1
       412   0x3 → 0x3   guest=1
       216   0x5 → 0x1   guest=1
```

## Две мои версии, обе опровергнуты этим же замером

**«Мы безусловно снимаем исполнение у гостевых областей»** — не подтвердилось. На штормящей
странице `x64_guest=0`, то есть строка `if (macrunner_x64_guest) unix_prot &= ~PROT_EXEC` к ней
не применяется, и `final=0x5` — исполнение на месте. Версия строилась на чтении кода и
совпадении класса (216 случаев `0x5 → 0x1` действительно есть), но к этой странице отношения
не имеет.

**«Запрос подстраничного размера молча не применяется»** — тоже нет. `size=4000` печатается
через `%zx`, то есть шестнадцатерично: `0x4000` = 16 384 байта = ровно одна страница хоста, и
`base` по ней выровнен. Ошибка чтения формата.

## Что установлено

Отказ **не снимается тем, что страницу делают исполняемой**. Обработчик отвечает на отказ
выдачей `r-x`, `mprotect` рапортует успех, и отказ приходит снова — двадцать четыре с половиной
миллиона раз подряд.

Самое простое объяснение, согласное со всеми наблюдениями: **отказ не на выборке команды, а на
записи**. `pc` лежит внутри той же страницы (`0xebb4ba43a` в `0xebb4b8000`), то есть код правит
сам себя — обычное дело для JIT. Обработчик классифицирует это как «нужно исполнение», выдаёт
`r-x` без права записи, запись отказывает снова.

**Это версия, а не факт.** Различить запись и выборку команды может только `dfsc` из `ESR`:
`0x0C-0x0F` права, `0x21` выравнивание, `0x04-0x07` трансляция. Печать floor26 его не выводит —
она знает лишь `addr/faults/pc`.
