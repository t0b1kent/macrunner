# Порядок задач Codex (по лестнице, НЕ вширь) — Notepad x64 tier

Закрываем нижнюю ступень (Win32/GDI) ПОЛНОСТЬЮ, прежде чем игры/D3D. По одной, серийно.

## 1. FREEZE (race в real-event delivery) — ПЕРВОЕ
См. RECURRING-HANG-IS-EVENT-DELIVERY-NOT-DEADLOCK.md (UPDATE3 ключевой).
- Ловится ТОЛЬКО от реальных кликов пользователя, не от синтетики → human-in-the-loop.
- Поставь трассу winemac.drv real-event path, координатор попросит пользователя кликать
  до фриза, найди точку обрыва цепочки. Фикс race в правильном слое (winemac.drv/queue).
- Verify: пользователь кликает/печатает интенсивно — НЕ зависает (стресс, не один прогон).

## 2. PERF — «чтобы Notepad летал» (translation/JIT)
NPP это GDI/CPU-app; «тормоза» = накладные трансляции HyperBridge, НЕ графика.
- СНАЧАЛА ИЗМЕРЬ, потом оптимизируй (не угадывай): профиль — куда уходит время в
  типичном NPP-сценарии (открытие меню/диалога, набор текста): JIT-compile vs interpreter
  fallback vs syscall/server round-trip vs winemac present. Какой компонент доминирует?
- Кандидаты по результату профиля: реально ли движок JIT-ит горячие блоки или падает в
  interpreter; тёплый ли translation-cache (hb_jit/translation-cache) или постоянные
  перекомпиляции; не молотит ли interpreter на непокрытых опкодах в горячем пути.
- Цель: NPP ощущается отзывчиво (меню/окна открываются быстро, ввод без лагов). Метрика —
  субъективно «летает» + объективно снижение времени в доминирующем компоненте.
- НЕ ломать корректность ради скорости; стоковый рендер не трогать.

## 3. INSTALLER + breadth (Win32, без GPU)
- Запусти НАСТОЯЩИЙ установщик Notepad++ через MacRunner.app: установка → реестр →
  ярлык → запуск установленной копии. Проверяет breadth Win32 (install path, не только
  распакованный payload).
- (32-бит версия — ОТДЕЛЬНЫЙ заход позже: x86-32 опкоды MOVZX/MOVSX/MUL/DIV/ADC/SBB/
  rotates не покрыты, см. X86-32BIT-COVERAGE-ATLAS — это крупная работа, не сейчас.)

И валидации D3D→Metal слоя (отдельно). Не прыгать вширь с открытым freeze.
